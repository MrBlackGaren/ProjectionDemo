# Android 屏幕投影演示项目

## 项目简介

本项目演示了如何使用Android的MediaCodec API将设备屏幕内容编码为H.264格式，并通过网络传输到另一个设备进行实时显示。核心技术包括：VirtualDisplay虚拟屏创建、MediaCodec视频编码与解码、H.264数据流处理、Socket网络传输。

## 项目结构

```
projection_demo/
├── server_app/          # 服务器端应用（发送屏幕内容）
│   └── src/main/java/com/projection/screen/server/
│       └── ScreenCaptureActivity.java  # 屏幕捕获与编码核心类
├── client_app/          # 客户端应用（接收并显示屏幕内容）
│   └── src/main/java/com/projection/screen/client/
│       └── MainActivity.java          # 数据接收与解码核心类
└── README.md            # 项目说明文档
```

## 核心功能

### 服务器端（发送端）功能

- ✅ 使用VirtualDisplay创建虚拟屏捕获屏幕内容
- ✅ 使用MediaCodec将屏幕内容编码为H.264格式
- ✅ 支持自动发送SPS/PPS参数和I帧
- ✅ 通过Socket网络传输H.264数据
- ✅ 支持连接状态监控和自动重连
- ✅ 内置H.264测试数据发送功能（用于调试）

### 客户端（接收端）功能

- ✅ 启动Socket服务器等待连接
- ✅ 接收并解析H.264数据流
- ✅ 使用MediaCodec解码H.264数据
- ✅ 通过SurfaceView实时显示解码后的视频内容
- ✅ 支持触摸事件回传（实验性功能）
- ✅ 详细的日志记录（便于调试）

## 技术原理

### 屏幕捕获与编码流程

1. **权限请求**：在应用启动前，需要用户授权屏幕录制权限
2. **虚拟屏创建**：使用`MediaProjection`和`DisplayManager.createVirtualDisplay()`创建虚拟屏
3. **编码器配置**：使用`MediaCodec.createEncoderByType()`创建H.264编码器
4. **数据编码**：虚拟屏内容自动渲染到编码器的输入Surface，编码器自动处理编码
5. **数据获取**：通过`MediaCodec.Callback`获取编码后的H.264数据
6. **网络传输**：将编码后的数据通过Socket发送到客户端

### 数据接收与解码流程

1. **服务器启动**：客户端启动Socket服务器等待连接
2. **数据接收**：接收服务器发送的H.264数据流
3. **数据解析**：寻找H.264起始码（0x00000001或0x000001）分割帧数据
4. **解码器配置**：使用SPS和PPS数据配置H.264解码器
5. **数据解码**：将帧数据送入解码器解码
6. **视频渲染**：通过SurfaceView显示解码后的视频内容

## 使用方法

### 准备工作

1. **设备要求**：需要两台Android设备（或一台设备和一个模拟器）
2. **网络连接**：确保两台设备在同一局域网内
3. **权限设置**：确保服务器端应用有屏幕录制权限

### 服务器端操作步骤

1. **启动应用**：打开`ScreenCaptureActivity`应用
2. **扫描设备**：点击"扫描设备"按钮，应用会自动扫描局域网内的客户端设备
3. **选择设备**：从列表中选择要连接的客户端设备
4. **开始投屏**：点击设备名称开始投屏
5. **查看状态**：应用会显示连接状态和IP地址信息

### 客户端操作步骤

1. **启动应用**：打开`MainActivity`应用
2. **等待连接**：应用会自动启动服务器并显示IP地址
3. **查看屏幕**：当服务器连接成功后，屏幕会显示服务器发送的内容

## 调试与故障排除

### 常见问题

1. **连接失败**
   - 检查两台设备是否在同一局域网内
   - 检查客户端应用是否已启动并显示IP地址
   - 检查防火墙是否阻止了端口8888的通信

2. **屏幕黑屏**
   - 检查服务器端是否已开始投屏
   - 查看客户端日志是否有解码错误
   - 尝试重新启动客户端应用

3. **画面卡顿**
   - 检查网络连接质量
   - 尝试减少视频编码比特率（在服务器端代码中修改`BIT_RATE`常量）

### 调试工具

1. **详细日志**：应用包含详细的调试日志，可以通过Android Studio的Logcat查看
2. **测试数据**：服务器端内置了H.264测试数据发送功能，用于测试网络传输和基础解码流程
3. **数据保存**：客户端会将接收到的H.264数据保存到本地文件，便于分析数据格式

### 日志标签

- **ScreenCaptureActivity**：服务器端日志标签
- **ClientDisplay**：客户端日志标签

## 技术参数

### 编码参数

- **视频编码**：H.264 (AVC)
- **分辨率**：1280x720
- **比特率**：2Mbps
- **帧率**：30fps
- **关键帧间隔**：1秒（30帧）
- **网络端口**：8888

### 网络传输

- **传输协议**：TCP Socket
- **数据格式**：原始H.264流（含起始码）
- **传输顺序**：SPS → PPS → I帧 → P帧

## 扩展与定制

```java

private int HEIGHT = 720;   // 高度
```

### 自定义比特率

在服务器端的`ScreenCaptureActivity.java`中修改以下常量：

```java
private int BIT_RATE = 2000000;  // 2Mbps
```

### 自定义网络端口

在客户端和服务器端修改以下常量：

```java
// 客户端 (MainActivity.java)
private static final int PORT = 8888;

// 服务器端 (ScreenCaptureActivity.java)
private static final int CAR_DEVICE_PORT = 8888;
```

## 注意事项

1. **权限要求**：服务器端应用需要`android.permission.MEDIA_PROJECTION`权限
2. **网络要求**：建议使用Wi-Fi网络，移动数据网络可能有延迟
3. **性能要求**：编码和解码过程会消耗较多CPU和内存资源
4. **安全性**：当前实现使用了简单的Socket连接，未加密传输数据

## 未来优化方向

1. **数据加密**：添加SSL/TLS加密保护传输数据
2. **自适应码率**：根据网络质量自动调整编码比特率
3. **错误恢复**：添加丢包重传机制
4. **多设备支持**：支持同时投屏到多个设备
5. **H.265编码**：使用更高效的H.265编码减少带宽消耗
